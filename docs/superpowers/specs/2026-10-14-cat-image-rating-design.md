# 猫咪 AI 图片与社区投票改版

日期：2026-10-14（America/New_York）

状态：用户已确认聊天中的产品方向和页面范围；本设计文档待用户审核。尚未开始产品代码实现。

## 1. 已确认的目标

把上一轮 CITY / VENT 吐槽应用改为猫咪 AI 图片社区，核心流程是：

**输入想法 → 选择猫咪和画风 → AI 生成猫图 → 预览并发布 → 社区投票。**

用户在三个方向中选择了“输入想法 → AI 生成猫图 → 社区投票”，随后确认以下范围：图片卡片首页、最新／热门／时间筛选、独立创作页、作品详情、个人作品页、复用提示词、深色与黄色视觉、中英文切换和 Google 登录。地点改为可选。

顺序必须是：先完成上一轮作业的产品和代码改版，再配置并验证 AI API，最后推进本周作业。文档不授权启用计费或传输新的密钥。

参考站：https://www.crackd.ai/ 。参考其图片卡片、投票和时间榜单结构；图片生成作为本应用的核心能力，沿用原创猫咪、爪印元素。使用自己的名称与图形，不复制参考站的品牌或用户内容。

## 2. 用户价值与范围

面向想把生活场景变成猫咪图片、并比较创意效果的用户。发布者能够找回自己的作品和原始想法、复用提示词继续创作；浏览者能够查看新作品和近期热门作品，并用投票参与筛选。

这轮解决三个具体问题：旧首页看不到可评价的图片；生成猫图被藏在吐槽表单里；用户没有集中查看和继续创作已有作品的入口。

采用工作名称 **CatCanvas / 猫咪画室**，后续改名不改变数据结构。保留既有 Next.js、Supabase、Google OAuth、Vercel 仓库和服务项目。保留旧吐槽、课程入口及已发布数据。

本轮不增加关注、私信、通知、付费、自动生成文案或图片编辑模型。复用提示词表示用已有参数重新创建作品，不表示修改原图片。

## 4. 页面与交互

### 首页 `/`

顶栏含猫咪标识、创作入口、我的作品、语言切换和登录／账号入口。主区域以图片卡片为中心，桌面双列，手机单列；简短标题说明产品用途。

卡片含猫图、公开场景描述、猫咪／画风标签、AI 来源、当前分数、赞／踩和详情入口。样例卡片含独立的样例标签，投票禁用且没有数字。图片用固定比例容器与 `object-fit: contain`，避免裁掉主体；为加载失败提供占位说明。

提供最新／热门切换和本周／本月／本年／全部筛选；默认最新、全部。时间范围表示作品发布时间窗口，热门按该窗口内作品的累计赞踩净分排序，不声称统计了窗口内发生的投票。以 America/New_York 的当前周、月、年起点计算边界，包含起点，未来时间不纳入。

每页 8 条，最多读取 9 条判断下一页；切换筛选重置页码。排序并列时按发布时间倒序、ID 排序，避免随机顺序。

每个登录用户对每件作品只能有一个当前投票：点击未选项新增；点击另一项切换；再次点击当前项取消。游客点击时进入现有 Google 登录流程。成功后重新读取当前选择和分数；失败保留原状态并显示可理解的提示。同一作品操作期间禁用重复点击。

### 创作页 `/create`

需要登录。页面上方说明“把你的想法画成猫咪”。主要输入是场景提示词，1–1000 个 Unicode 字符。支持现有六种猫咪和三种画风，使用翻译后的选项名。

作品标题可选，最多 120 字符；未填写时从场景描述生成长度受限的文字标题，此操作只是截取用户输入，不调用 AI。地点可选，最多 120 字符。场景描述将随作品公开展示，输入区明确提示公开范围。

生成成功才显示真实预览、重新生成和发布。重新生成失败保留上一张成功图片和对应 generation ID。移除预览只解除当前表单关联，不删除历史作品或其他生成记录。发布与生成期间禁用重复操作。

保存本机草稿只存提示词、标题、地点、品种、画风及语言；按用户 ID 隔离，不存图片签名 URL、凭据或虚假的 generation ID。退出账号后不展示其他账号的草稿。提供明确的保存／清除操作，不能把本机保存误称为云端保存。

旧 `/rants/new` 入口重定向到 `/create`。API 未启用时允许保存草稿和查看参数示意，生成与发布不可用，并有状态说明。

### 作品详情 `/rants/[id]`

继续沿用既有稳定地址。猫图作品展示大图、标题、场景描述、可选地点、发布时间、AI 来源、投票和评论。旧文本吐槽继续以兼容布局展示。

公开页面不暴露生成记录的系统提示词、私有资料或投票人列表。仅作品本人可从这里读取自己的原始生成参数并复用；其他用户只看到公开场景描述。

评论继续采用现有长度、分页和登录限制。作品不存在显示 404，查询失败显示错误，不作为空作品处理。

### 我的作品 `/my-cats`

需要登录。展示本人已发布的 AI 猫图，按最新排序，含图片、发布时间、分数、查看详情及复用提示词。空状态指向创作页。

“复用提示词”以拥有者可读取的真实 generation 记录为来源，把提示词、品种、画风及语言填入新表单；创建新的生成，不覆盖原作品。私有提示词不写进 URL 查询参数。只读原始生成记录也必须校验本人权限。

本轮不增加删除、作品编辑、收藏或未发布生成记录的完整管理界面。

## 5. 视觉与语言

采用接近参考站的炭黑背景、深灰卡片、黄色主按钮，辅以原创猫咪标识和少量爪印。导航、表单、状态、错误、样例标签、文件按钮和无障碍名称全部覆盖 English／简体中文；保留用户语言选择。

用户的标题、描述、评论与生成内容保持原语言。按钮有键盘焦点，投票暴露按下状态与可读标签；色彩不是唯一状态信号。手机上按钮和表单可操作，不出现横向滚动。

## 7. 数据与迁移

继续使用 `rants`、`ai_generations`、`rant_votes`、`rant_comments` 和私有 `ai-cat-images` bucket。猫图作品以数据库生成的 `ai_image_path` 与 image generation 关联识别；旧文字示例与普通用户照片不冒充 AI 猫图。

必须先检查现有 `20261008000004_ai_cat_images.sql` 是否已应用。新迁移不能在未知线上状态下直接重复执行它。

新增迁移负责：

1. 放宽 `rants.location` 长度约束至 0–120，空字符串表示未提供，UI 不显示空地点。保留旧非空地点数据。
2. 增加猫图分页 RPC：只返回已发布且关联 `media_type='image'` 的可信作品，返回卡片必要字段、公开参数和聚合票数；通过用户上下文只返回本人投票值。不返回公开 `user_id`、系统提示词或完整私有生成记录。
3. 同一查询接口校验排序、窗口、偏移和数量，并支持仅本人作品模式；本人筛选由 `auth.uid()` 决定，客户端不能指定任意用户获取私有参数。
4. 在数据库发布引用校验中保障：图片路径由拥有者匹配的 image generation 推导；客户端不能自填他人的路径或伪造 AI 来源。仍保留历史文本发布记录的兼容性。

公开卡片通过服务端批量签名已发布图片，沿用私有 bucket 策略与短期 URL。当前页面访问时重新获得签名；不把过期 URL 永久保存在数据库或本机草稿。

原始 prompt、系统 prompt、provider、model、品种和画风保存在现有生成记录；本人才能读取原始私有记录。公开页面只读取专门投影的公开字段。客户端不能创建 `is_example`、可信 provider 或成功生成记录。

## 8. 错误与配置状态

- API 关闭：显示未启用，返回既有明确错误；不调用供应商，不预留额度。
- 缺少迁移或查询失败：展示设置未完成或加载失败；样例只能通过明确的样例入口显示。
- 供应商失败：保留输入与上一张成功预览，按现有流程释放预留额度并清理孤立上传，不记录假成功。
- 未登录／会话过期：写入仍在服务端和数据库拒绝，UI 提示登录。
- 投票／评论失败：保留旧分数或评论输入，避免错误乐观状态。
- 日志不输出密钥、授权头、签名 URL 或完整供应商响应中的潜在敏感内容。
